# 数据工程链路开发平台

面向数据接入、原始落地、清洗转换、分层建模、质量校验、血缘追踪与数据服务发布的数据工程开发平台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm ci
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

## 清洗后数据集（CLEA-0018 场景）

数据清洗模块在规则维护之外，还提供清洗执行能力：读取输入数据集、空值策略、
格式表达式、异常阈值和规则版本，逐行清洗并生成清洗后数据集，每条输出记录保留
清洗编号、规则版本和异常处理结果（以及原始行标识、异常原因、原始值、行号）。

- **批次状态机**：草稿 → 运行 → 完成 / 失败，单向流转；失败可恢复运行
  （不重置游标与临时结果，不回到草稿）；完成 / 失败可归档，归档是终态，
  归档后不允许切换规则版本。
- **规则版本冲突**：同一清洗编号存在多个已启用版本时，采用生效日期最新的一版
  （相同则取版本号较大者），决策理由写入批次 `版本决策`。
- **断点续做**：每条记录处理完即推进游标。CLEA-0018 的 V1（`strict_date` 严格
  表达式）在第 120 条遇到无法解析的日期 `2026-13-45` 时中断：前 119 条成功记录
  保留在临时结果中不发布；修复规则版本（V2：`date:YYYY-MM-DD`）后从第 120 条
  续做，前 119 条不重复清洗、不重复导出，新执行批次只含第 120 条起的记录。
- **异常分支**：空值走空值策略（空值补全）；非空值一律过格式表达式，非空但格式
  错误的记录进入异常分支而不是默认为成功；异常与失败记录保留原始值、规则版本
  和行号，供质量人员回查。
- **落库一致性**：结果发布与质量报告通过同一条落库日志提交；服务启动时重放
  「待提交」日志，保证两侧数据一致；中断的运行批次恢复时标记为失败。
- **质量报告**：保留异常阈值与生效日期，说明跳过数量；规则版本变化时另起版本。
- **发布与去重**：批次完成时临时结果原子发布为新一代清洗后数据集，上一代同时
  转为已替换——去重模块只读取已发布部分，任何时刻只有一代已发布输出，不会同时
  收到两版；重算后回写清洗调用链的「去重重算」步骤。

主要接口（均在 `/api/cleaning` 下）：

| 接口 | 说明 |
| --- | --- |
| `POST /runs` / `GET /runs` / `GET /runs/{id}` | 创建批次、批次列表、批次详情（游标、版本决策、调用链） |
| `POST /runs/{id}/start` `/resume` `/archive` | 启动、从失败记录恢复、归档 |
| `GET /runs/{id}/records` | 当前执行段记录（新执行批次） |
| `GET /datasets/{code}` / `GET /datasets/{code}/anomalies` | 清洗后数据集（默认已发布）、异常回查 |
| `GET /reports` | 质量报告 |
| `GET /inputs/{dataset_name}` | 输入数据集原始行回查 |
| `POST /api/dedup/{id}/recompute` / `GET /api/dedup/results` | 去重重算与结果 |
